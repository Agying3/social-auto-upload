# Tujue AutoSend 项目技术文档

> 多平台视频一键发布桌面工具 · 基于 social-auto-upload 的 GUI 增强版

---

## 一、项目概述

**Tujue AutoSend** 是一个 **Windows 桌面 GUI 应用**，支持在抖音、快手、小红书、B站、视频号、TikTok 六大平台一键发布视频。底层基于浏览器自动化技术，模拟用户在浏览器中的真实操作来完成登录和发布流程，避免被封禁的 API 调用方式。

核心设计理念：**让非技术用户双击 EXE 就能用**，不需要装 Python、配环境、敲命令行。

## 四、运行原理

### 4.1 启动流程

```
1. 双击 TujueAutoSend.exe 或 python app.py
       │
2. app.py 启动
   ├── 初始化日志系统 (loguru)
   ├── 导入 backend 模块 → Flask 自动初始化
   ├── 启动 Flask 于 127.0.0.1:18592
   └── 等待 Flask 就绪（轮询 /api/platforms）
       │
3. 创建 pywebview 桌面窗口
   ├── frameless=True (无边框，自定义标题栏)
   ├── easy_drag=True (窗口可拖拽)
   ├── transparent=False (直角窗口)
   ├── 注入 WindowApi (minimize/close 方法)
   └── 加载 http://127.0.0.1:18592
       │
4. WebView2 渲染 gui.html
   ├── 加载壁纸轮播
   ├── 初始化太阳导航
   ├── 请求 /api/platforms 获取平台状态
   └── 显示首页 Dashboard
```

### 4.2 发布流程

```
用户操作：选择视频 → 填写标题/描述 → 勾选平台 → 点击发布
       │
       ▼
POST /api/upload  { platforms, video_path, title, desc, tags }
       │
       ▼
upload_worker()  后台线程启动
       │
       ├── 检查 Cookie 有效性 (/api/check-cookie)
       ├── 从 settings 读取 concurrent_uploads (默认 3)
       │
       ▼
ThreadPoolExecutor(max_workers=3)
       │
       ├── Thread 1: _do_upload_sync("douyin", ...)  → 抖音发布
       ├── Thread 2: _do_upload_sync("kuaishou", ...) → 快手发布
       └── Thread 3: _do_upload_sync("xhs", ...)      → 小红书发布
              │
              ▼
       _do_upload(platform, ...)
              │
              ├── 查找对应 Cookie 文件
              ├── 导入平台 Uploader 类
              ├── 创建 asyncio 事件循环
              ├── 实例化 Uploader → 调用主方法
              └── patchright 启动 Chromium 浏览器
                     │
                     ├── 加载 Cookie → 刷新页面
                     ├── 导航到发布页
                     ├── 填写标题/描述/标签
                     ├── 通过 file_chooser 上传视频
                     ├── 等待上传完成（轮询进度）
                     ├── 点击发布按钮
                     └── 检测发布成功信号
```

### 4.3 浏览器自动化原理

每个平台的 Uploader 类封装了完整的浏览器操作流程：

```
patchright.launch(headless=False)
    │
    ├── 加载已保存的 Cookie (storageState)
    ├── 创建 BrowserContext (隔离的浏览器环境)
    ├── 打开 Page → goto(发布页URL)
    │
    ├── 等待关键元素加载 (wait_for_selector)
    ├── 关闭引导弹窗/广告
    ├── 定位文件输入框 → file_chooser.set_files(video_path)
    ├── 等待上传进度 (轮询检测上传状态)
    ├── 填写标题、描述、标签 (type/fill)
    ├── 选择分区/分类 (B站)
    ├── 设置定时发布时间
    ├── 点击发布按钮
    │
    ├── 检测发布成功
    │   ├── Toast 提示
    │   ├── 页面跳转
    │   ├── 表单重置
    │   └── 提交成功文案
    │
    └── 关闭浏览器 → 返回结果
```

## 五、功能详解

### 5.1 首页 Dashboard

- **导航卡片**：4 个功能入口（一键发布/登录管理/发布历史/系统设置）
- **壁纸轮播**：6 秒切换，支持自定义壁纸管理
- **太阳导航**：弧形悬浮按钮，双击弹出退出/切换账号菜单
- **实时状态**：显示当前登录平台数和就绪状态

### 5.2 一键发布

- **视频选择**：支持拖拽或点击上传（mp4/mov/avi 等格式）
- **内容编辑**：标题、描述、标签输入
- **平台多选**：勾选要发布的目标平台
- **定时发布**：日期时间选择器，支持延迟发布
- **并发控制**：可配置同时发布的平台数（1-6）
- **B站专属**：分区选择、封面图片上传
- **发布进度**：实时显示每个平台的上传状态
  - ⏳ 等待中 → 📤 上传中 → ✅ 成功 / ❌ 失败
- **重试机制**：发布失败可在历史记录中重试

### 5.3 登录管理

- **平台卡片**：6 大平台独立卡片，显示登录状态
- **扫码登录**：点击登录 → 浏览器弹窗 → 扫码 → Cookie 自动保存
- **状态管理**：
  - 🟢 已登录 → 显示用户名/头像
  - 🟡 已过期 → 黄色徽章 + Toast 提醒
  - ⚪ 未登录 → 点击即可登录
- **Cookie 检测**：
  - 手动检测：点击「检测登录状态」按钮
  - 自动检测：每 30 秒静默检测已登录平台
  - 5 分钟缓存，避免频繁请求
- **退出登录**：双击太阳 → 选择退出/切换账号
- **多账号支持**：同一平台可保存多个账号 Cookie

### 5.4 发布历史

- **历史列表**：展示所有发布记录（平台/时间/状态）
- **筛选搜索**：按平台、状态筛选，关键字搜索
- **重试功能**：失败记录可一键重新发布（保留原有视频和文案）
- **数据持久化**：SQLite 数据库存储，重启不丢失

### 5.5 系统设置

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| 并发上传数 | 同时发布的平台数量 | 3 |
| 浏览器模式 | headed/headless | headed（防止反爬） |
| Chrome 路径 | 自定义浏览器路径 | 自动检测 |
| 壁纸管理 | 添加/删除/排序壁纸 | 内置 2 张 |
| 缓存管理 | 清除 Cookie/设置/历史 | — |
| 配置导入导出 | 备份和恢复设置 | — |
| 图标管理 | 自定义平台图标 | 内置 SVG |

### 5.6 重试机制

每个平台的 Uploader 内置 **3 轮重试**：

1. **第 1 轮**：正常发布流程
2. **第 2 轮**：若失败 → 刷新页面 + 清理弹窗 → 重试
3. **第 3 轮**：若仍失败 → 关闭浏览器重启 → 重新走完整流程

每轮失败都会截图保存，便于调试。

## 六、平台支持详情

| 平台 | 上传器模块 | 自动化引擎 | 视频 | 图文 | 特殊说明 |
|------|-----------|-----------|:----:|:----:|----------|
| 抖音 | `douyin_uploader` | patchright + Chromium | ✅ | ✅ | 最完善的实现(~1189行)，支持 shepherd 弹窗关闭、双模式 |
| 快手 | `ks_uploader` | patchright + Chromium | ✅ | ✅ | 需关闭 microSupport 弹窗 |
| 小红书 | `xiaohongshu_uploader` | patchright + Chromium | ✅ | ✅ | 代码完整，后端 15 行修复即可接入 |
| B站 | `bilibili_uploader` | patchright/biliup | ✅ | ❌ | file_chooser 事件上传，封面必填，Vue 事件触发 |
| 视频号 | `tencent_uploader` | patchright + Chromium | ✅ | ❌ | Wujie 微前端 Shadow DOM，JS click() 代替 mouse.click() |
| TikTok | `tk_uploader` | playwright + Firefox | ✅ | ❌ | 唯一使用 Firefox 的平台 |
| YouTube | 占位 | — | 🔲 | 🔲 | 开发中 |
| Instagram | 占位 | — | 🔲 | 🔲 | 开发中 |
| X | 占位 | — | 🔲 | 🔲 | 开发中 |
| 百家号 | `baijiahao_uploader` | — | 🔲 | 🔲 | 代码存在，未接入后端 |

### 各平台反爬策略适配

- **抖音/快手/小红书/B站/视频号**：`headless=False` 强制有头模式，headless 会被反爬拦截
- **B站**：投稿按钮是 `<span>` 标签，需 `dispatchEvent(new MouseEvent(...))` 触发 Vue 事件
- **视频号**：表单在 wujie-app Shadow DOM 中，需用 JS `click()` 代替 Playwright `mouse.click()`
- **TikTok**：使用 Firefox（非 Chromium），国际站反爬策略不同

## 八、打包分发

### PyInstaller 配置要点

```

├── onefile (单文件 EXE)
├── runtime_tmpdir → G 盘 (C 盘空间 < 1GB)
```

### 打包前检查

- 确保无 `TujueAutoSend` 进程运行（EXE 被锁会损坏）
- 清理 C 盘 `_MEI*` 临时目录（每个 ~300MB）

## 九、已知技术债务

| 优先级 | 问题 | 影响 |
|:---:|------|------|
| 🔴 P0 | 小红书后端接入（代码完整，仅缺 backend.py 15 行连接） | 小红书平台不可用 |
| 🟡 P1 | 各平台健壮性改造未迁移（仅抖音完成 3 轮重试） | 快手/B站/视频号稳定性不足 |
| 🟡 P1 | 百家号接入 | 缺失一个国内主流平台 |
| 🟢 P2 | build_gui.py 5300 行模板维护困难 | 前端迭代效率低 |
| 🟢 P2 | if-elif 平台分支 120+ 行，应改为策略模式 | 扩展新平台需改动核心代码 |
| 🟢 P2 | 发布失败自动重试功能未实现（配置项已就位） | 偶发网络波动导致发布失败 |
| 🟢 P2 | 无自动化测试 | 回归风险高 |
