## 四、进一步可提升方案

### 4.1 短期（1-2 周可完成）

#### 4.1.1 小红书后端接入（收益最高）
- **现状**：`xiaohongshu_uploader/main.py` 代码完整，`backend.py` 直接抛 NotImplementedError
- **改动**：在 `login_worker` 添加 xhs 分支 + `_do_upload` 添加小红书调用
- **影响**：解锁小红书视频/图文发布，提升产品覆盖

#### 4.1.2 发布前 Cookie 预检拦截
- **现状**：Cookie 过期检测已实现但仅被动展示
- **改动**：在 `doPublish()` 中，点击发布按钮后先检查 `cookieValidityCache`，过期则拦截并提示
- **影响**：避免用户发布到一半才发现 Cookie 过期

#### 4.1.3 发布进度百分比
- **现状**：进度仅显示文字状态（"上传中…""发布成功"）
- **改动**：通过 patchright CDP 抓取浏览器上传进度条 → 后端暴露 `/api/status` 百分比字段
- **影响**：用户对大视频上传有明确预期

#### 4.1.4 发布失败自动重试
- **现状**：有重试配置项但无对应功能
- **改动**：`_do_upload_sync` 中捕获异常后，根据 settings 的 `retry_count` 自动重试
- **影响**：提升发布成功率

### 4.2 中期（1 个月）

#### 4.2.1 图文发布支持
- **现状**：小红书 Note 上传器代码完整，快手也有 Note 类，但 GUI 无入口
- **改动**：发布页增加"内容类型"选择 → 视频/图文，切换对应上传器
- **影响**：解锁图文笔记分发场景

#### 4.2.2 定时发布
- **现状**：发布页已有日期选择器和定时开关，但后端未实现
- **改动**：后端在 `publish_date` 不为 0 时跳过立即发布，写入定时任务队列
- **影响**：支持节假日/高峰时段定时发布

#### 4.2.3 批量发布
- **现状**：一次只能发布一个视频
- **改动**：发布页支持多视频文件选择 → 排队逐个发布
- **影响**：效率提升，适合多视频批量操作

#### 4.2.4 根目录清理
- **现状**：~70 个 `_debug_*`、`_check_*`、`_diag_*` 临时脚本
- **改动**：移动到 `tools/debug/` 子目录或删除
- **影响**：项目可维护性

### 4.3 长期（2-3 个月）

#### 4.3.1 前端项目重构
- **现状**：`build_gui.py` 5330 行 Python 模板字符串，维护噩梦
- **方案 A**：激活 `sau_frontend/` Vue3 项目，替换 pywebview 内嵌
- **方案 B**：将 build_gui.py 拆分为独立 HTML/CSS/JS 文件 + 构建脚本
- **收益**：大幅提升可维护性和迭代速度

#### 4.3.2 SaaS 化改造
- **现状**：纯桌面应用，配置文件本地存储
- **方案**：后端改为常驻服务 + Web 前端，支持多用户
- **改动**：用户体系 + 数据库 + 前端重构 + 部署
- **收益**：从工具变为平台

#### 4.3.3 新平台扩展
- **YouTube**：YouTube Data API v3 上传，OAuth2 授权
- **Instagram**：浏览器自动化 + Instagram Graph API
- **X (Twitter)**：Twitter API v2 上传
