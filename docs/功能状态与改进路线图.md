# Tujue AutoSend — 功能状态与改进路线图

> 撰写时间：2026-04-28
> 对应版本：dist/TujueAutoSend.exe（2026-04-27 ~129.5 MB）+ 最新 gui.html（2026-04-28）

---

## 一、项目愿景

将 TujueAutoSend 打造成**创作者的一站式视频分发中枢**——只需一次操作，视频同步发布到所有目标平台，最大化内容触达范围，减少重复劳动。

### 2.2 前端 GUI

- **透明背景 + 壁纸轮播**：pywebview 透明窗口，6 秒切换背景图，底部圆点指示器可点击跳转
- **平台 SVG 图标**：9 个平台均使用矢量 SVG（而非 emoji），纯 ASCII 安全渲染
- **4 页面 SPA**：
  - **首页**：欢迎区 + 快捷功能卡片（发布视频 / 登录管理 / 发布历史 / 设置）
  - **发布页**：视频上传 → 选择平台（卡片式，支持一键全选）→ 填写标题/描述/标签 → 发布
  - **登录管理页**：平台账号列表、扫码登录、Cookie 校验、切换账号
  - **设置页**：浏览器模式、并发数、默认标签、自动重试次数
- **发布历史页面**：记录每次发布的平台/状态/时间，支持筛选、重试、删除
- **导入/导出配置**：settings.json + history.json 打包迁移
- **缓存清理**：一键清除 Cookie 和临时文件

### 2.3 后端架构

- **Flask REST API**（24 个端点）：登录、上传、状态、历史、设置、诊断
- **异步登录会话**：二维码实时渲染到前端，不阻塞 UI
- **视频文件先上传后端**：`/api/upload/video` → `uploads/` → 解决浏览器 `file.path` 不可用问题
- **多账号管理**：Cookie 文件名即账号名，支持多账号切换
- **反爬即时终止**：检测"操作频繁/验证/captcha/人机"关键字立即停止
- **浏览器崩溃检测**：`page.is_closed()` + `document.readyState` 双检
- **3 轮整体重试**：异常 → 关闭浏览器 → 等 5 秒 → 重启 Chrome → 重走全流程

## 三、当前存在的不足

### 3.1 平台接入不完整

#### 🔴 小红书 — 优先级：**最高**

**现状**：`xiaohongshu_uploader/main.py` 中 `XiaoHongShuVideo`、`XiaoHongShuNote`、`xiaohongshu_setup()` 均已完整实现。

**问题**：backend.py 的 `login_worker` 中没有 `xhs` 分支，`_do_upload` 中直接抛 `NotImplementedError`。

**修复方法**（约 15~30 行代码）：
1. 在 `login_worker` 中添加 `xhs` 分支，调用 `xiaohongshu_setup()`
2. 在 `_do_upload` 中添加小红书上传调用
3. 参考抖音的接入方式

---

#### 🔴 百家号 — 优先级：**中**

**现状**：`uploader/baijiahao_uploader/main.py` 已实现 `baijiahao_cookie_gen()` 和 `cookie_auth()`，但 backend.py 中**完全没有百家号的任何引用**。

**问题**：百家号完全没有接入 GUI，也不存在于平台配置中。

**修复方法**：
1. 在 backend.py 的 `PLATFORM_MAP` 中添加百家号
2. 在 `login_worker` 中添加百家号登录分支
3. 在 `_do_upload` 中添加百家号上传分支

---

#### 🟡 B站 — 优先级：**中**

**现状**：`bilibili_uploader/` 有完整代码，`runtime.py` 管理 biliup CLI 二进制下载。

**问题**：
- login_worker 中无 bilibili 分支
- biliup 二进制从 GitHub 下载（国内网络可能失败）
- Cookie 格式需转换
- stream_gears API 已被官方停用（"投稿工具已停用"）

**修复方法**：
1. 确认 biliup 二进制可用（或内置国内镜像）
2. 实现 patchright 浏览器自动化（类似快手），替代已停用的 stream_gears
3. 在 backend.py 中接入

---

#### 🟡 快手 / 视频号 / TikTok — 优先级：**低**

**现状**：后端已接入，但发布流程**未验证**。

**问题**：没有经过真实发布测试，健壮性改造未应用，可能存在未知的反爬或页面变化。

**修复方法**：参考抖音的健壮性改造逐个平台迁移。

---

#### 🟢 YouTube / Instagram / X — 优先级：**低（长期）**

**现状**：完全占位，`supported: False`。

**问题**：完全没有代码。

**修复方法**：需要全新开发。

### 3.2 功能缺失

#### 🔴 并发上传未真正实现

- `settings.json` 中有 `concurrent_uploads` 配置项
- `backend.py` 的 `upload_worker` 仍是串行执行（`for platform in valid_platforms`）
- 多平台发布速度受限

**改进方向**：
- 使用 `asyncio.gather()` 或 `ThreadPoolExecutor` 实现真正的并发
- 添加并发数限制（避免过多浏览器实例同时运行）
- 提供"串行模式"开关（部分平台可能对并发有限制）

---

#### 🟡 定时发布

- 当前所有发布都是即时发布
- 创作者常需要在特定时间发布（如节假日高峰、粉丝活跃时段）

**改进方向**：
- 设置页面添加"定时发布"开关
- 后端使用 APScheduler 或后台线程轮询定时任务
- 定时任务写入 history.json 持久化

---

#### 🟡 上传进度实时反馈

- 当前前端通过轮询 `/api/status` 获取进度（轮询间隔约 2 秒）
- 无百分比进度条，仅有状态文字（"上传中…""填写标题中…"）

**改进方向**：
- 抖音/快手：通过 patchright CDP 获取文件上传进度
- 视频号：WebUploader 组件无公开进度 API，但可检测文件 input 大小变化
- 添加全局进度条（前端）

---

#### 🟡 视频封面设置

- 当前所有平台均未实现自定义封面
- 大多数平台会自动截取视频某一帧作为封面

**改进方向**：
- 发布页添加"选择封面"功能（截图或上传本地图片）
- 优先在抖 B 快三大平台实现

---

#### 🟡 图文/纯文字发布

- 当前仅支持视频发布
- 快手、抖音、小红书均支持图文帖子

**改进方向**：
- 发布页增加"内容类型"选择（视频 / 图文 / 纯文字）
- 小红书图文已有完整实现（`XiaoHongShuNote`），只需后端接入 + 前端 UI

---

### 3.3 架构问题

#### 🟡 `_do_upload` 平台分支膨胀

- 当前用 120+ 行 if-elif 分支处理 6 个平台
- 每次增删平台都要修改此处

**改进方向**：
- 使用**策略模式**：每个 uploader 实现统一接口（`upload()`, `setup()`, `check_cookie()`）
- backend.py 通过反射加载：`from uploader import get_uploader(platform)`
- 参考 `BaseVideoUploader` 抽象基类

---

#### 🟡 缺少自动化测试

- `tests/` 目录存在但内容有限
- 各平台只能靠手动测试验证

**改进方向**：
- 端到端测试：模拟完整的发布流程（mock 浏览器或用 test cookie）
- 回归测试：每次提交自动测试各平台登录流程
- 使用 pytest + pytest-asyncio

---

#### 🟡 打包后配置不可修改

- `conf.py` 被打包进 exe 后不可编辑
- 打包后无法修改 Chromium 路径、headless 模式等

**改进方向**：
- 将 `conf.py` 中的可配置项写入 `settings.json`
- exe 启动时从 `%APPDATA%/TujueAutoSend/settings.json` 读取
- 或在 exe 同目录下放 `settings.json` 覆盖默认配置

---

### 3.4 反爬与稳定性

| 问题 | 影响平台 | 说明 |
|------|---------|------|
| headless 发布被拦截 | 抖音、视频号 | 必须 headed，增加资源消耗 |
| 浏览器崩溃无自动恢复 | 全部平台 | 健壮性改造仅抖音完成 |
| 反爬关键字更新 | 全部平台 | 需持续监控平台页面变化 |
| 网络超时配置不一致 | 全部平台 | 各平台超时参数各异，难以维护 |

## 四、改进路线图

### 阶段一：快速完善（1~2 周）

> 目标：让当前 4 个已接入后端的平台（抖音/快手/视频号/TikTok）都能稳定发布

- [ ] **小红书后端接入**（~30 行代码，收益最高）
- [ ] **健壮性改造迁移**：抖音 → 视频号 → 快手 → TikTok
- [ ] 各平台发布流程实测（记录失败原因，更新选择器）
- [ ] B站 biliup 二进制 + Cookie 转换接入

### 阶段二：功能增强（1 个月）

- [ ] 真正的并发上传（asyncio.gather）
- [ ] 定时发布功能
- [ ] 视频封面自定义
- [ ] 图文发布支持（小红书图文已有代码）
- [ ] 百家号完整接入

### 阶段三：生态扩展（长期）

- [ ] YouTube / Instagram / X 平台开发
- [ ] 策略模式重构（消除 if-elif 膨胀）
- [ ] 自动化测试体系
- [ ] 用户账号体系（云端配置同步）
